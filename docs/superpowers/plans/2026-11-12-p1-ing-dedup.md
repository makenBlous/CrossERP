# 疑似重复实体与合并实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 `superpowers:executing-plans` 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 仅实现任务卡列出的两个接口：疑似重复实体分页列表和中风险合并；覆盖已有 SKU，供应商/客户只通过注册表保留扩展点，不写假处理器。P1 ingest 的原件落地、清洗、投射等其它接口属于并行任务，本计划不扩展范围。

**架构：** 新增 `dedup_candidate` 持久化模型与 `0040_ing_dedup` 迁移（本树 `alembic heads` 已验证唯一 head 为 `0024_audit_approval`；`0024_ontology` 由 `0022_iam` 作为祖先串入）。路由只通过 `PermissionService` 和 `ActionDispatcher` 执行查询/合并。合并服务按实体类型注册处理器；SKU 处理器把重复行软停用、把别名/来源并集写入 canonical SKU 和 EntityVersion，并在同一事务内迁移 DocumentLink 引用；未注册供应商/客户类型固定返回 `NOT_FOUND`，不伪造成功。

**技术栈：** Python 3.12+、FastAPI、SQLAlchemy 2、Alembic、Pydantic 2、pytest。
