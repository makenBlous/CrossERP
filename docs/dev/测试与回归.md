# 测试与回归

**适用范围：** CrossERP 后端、前端静态原型和推送前验收。**状态：仓库内命令以当前文件为准；监督方脚本的路径和内容未核实。** 不在本机运行构建、测试或预览时，遵守任务的禁止事项；本文提供给有授权的维护者复制执行。

## 仓库内检查

命令来自当前 `pyproject.toml`、`frontend/package.json`、`scripts/` 和 `.github/workflows/`：

```powershell
# Python 依赖和全部可选驱动
uv sync --locked --all-extras

# Python 格式、静态检查和类型检查
uv run ruff format --check .
uv run ruff check .
uv run mypy

# SQLite 默认测试与覆盖率门槛
uv run pytest --cov=crosserp --cov-fail-under=80 -q

# 文档链接和数据库授权覆盖检查
uv run python scripts/check_doc_links.py
uv run python scripts/check_grants_cover_all_tables.py

# 合并前检查。对照 main 的合并基点，拦截放宽的安全断言、防御性写法和自写共用逻辑。
uv run python scripts/check_merge_guard.py --base <main 合并基点>

# 前端（在 frontend/ 目录执行）
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm exec eslint . -c .eslintrc.cjs --ext .ts,.js,.cjs,.vue,.tsx,.jsx
node node_modules\vite\bin\vite.js build
```

`.github/workflows/ci.yml` 还会在 Python 3.12/3.14、Windows/Linux/macOS 和 SQLite/MySQL 8.4/PostgreSQL 18 矩阵中运行测试，并执行安装 smoke、离线评测和前端构建；CI 的测试数据库密码只存在于 CI 服务配置，文档不复制任何凭据。

数据库回归命令按授权环境设置 `CROSSERP_TEST_DATABASE_URL` 后运行：

```powershell
$env:CROSSERP_TEST_DATABASE_URL = "mysql+pymysql://<USER>:<PASSWORD>@127.0.0.1:3306/crosserp?charset=utf8mb4"
uv run pytest -m db

$env:CROSSERP_TEST_DATABASE_URL = "postgresql+psycopg://<USER>:<PASSWORD>@127.0.0.1:5432/crosserp"
uv run pytest -m db
```

正式环境以 MySQL 8.4 LTS 为主；PostgreSQL 只用于备选兼容回归，替换条件见 [08 第 11.3 节](../design/08-后端模块与API设计.md#113-什么情况下必须换-postgresql)。不要把真实密码写进命令历史、文档或仓库。

## 监督方本机脚本

下面的脚本位于监督方本机 `%TEMP%\cx-pw\`，未入库，路径与内容未核实。这里只记录用途，不编造命令行参数：

- `par_tree_check*.ps1`、`verify_merged.ps1`：类型检查、ESLint、构建、smoke A–E、基线回归、角色导航（21 个角色，AI 开/关）、流程 a–e、UX 和最终检查。
- `run_all`：xperm 系列、仓库脚本和 `verify-fin-*` 汇总回归。
- `xperm_merge`：对照历史权限样本，检查权限收紧是否被错误放宽。
- `par_chat_logout.js`：对话登出路径的回归检查。

这些脚本不能替代仓库命令，也不能据此推断接口或权限；如脚本和 08、OpenAPI、权限样本冲突，暂停并报告。

## 推送门槛

推送前必须满足：所有检查 exit=0；测试输出中 0 个 `FAIL`；ESLint 输出 0 个 error；密钥扫描 0 命中。失败项要修复或记录为明确的未决问题，不能删除测试、跳过检查、降低断言或用 mock 冒充验收。推送只使用普通 `git push origin main`，不强制推送。

## 密钥扫描

对本次修改文件执行规则扫描，并人工核对所有示例均是占位符：

```powershell
rg -n -i "(api[_-]?key|secret|password|token)\s*[:=]\s*['\"]?[A-Za-z0-9_\-]{12,}|sk-[A-Za-z0-9]{16,}|BEGIN [A-Z ]*PRIVATE KEY" <本次修改文件>
```

扫描命中需要逐条确认是否是占位符；真实密钥命中即停止，不得提交。
