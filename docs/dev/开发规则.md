# 开发规则

**适用范围：** CrossERP 后端、静态前端和文档的日常开发。**状态：已实现规则与目标设计分开记录；接口和实体目标仍是仅设计。** 本文只写长期可执行的做法，具体接口以 [08 后端模块与 API 设计](../design/08-后端模块与API设计.md) 为准。

## 工作树与提交

- 用 `git worktree add --detach <path> main` 创建分离头工作树，不新建分支。这样并行任务不会把半成品混入其他工作树。
- 完成后把提交整合到 `main`，工作树已经合入且干净时及时执行 `git worktree remove <path>`。被锁住的目录不要强删，也不要杀不认识的进程；先查清占用者。
- 不打 tag、不发 Release、不 `push --force`、不 `git reset --hard`、不改已推送历史。这些操作会破坏验收证据或覆盖他人的工作。
- 保留不认识的用户改动；开始和结束都检查 `git status --porcelain`，只处理任务允许的文件。

## 前端实现

- 优先复用 Vuexy / Vuetify 组件。每批开发单独做一次复用审计，并在 [前端开发规范](../../frontend/docs/前端开发规范.md) 和现有 [复用审计记录](../../frontend/docs/component-reuse-audit.md) 中留下依据，避免重复造组件。
- `frontend/` 当前是 Vue 3 + TypeScript + Vuetify 3 + Vite 的静态 mock；真实接口必须按 [对接真实接口](../../frontend/docs/对接真实接口.md)、[OpenAPI 草案](../design/08/openapi-draft.yaml) 和实体目录切换，不从 mock 猜字段。
- 不使用 5173 端口；4173 是主人 maken 的预览端口，不要占用。其他端口先在任务记录中说明用途。
- Windows 构建用 `node node_modules\vite\bin\vite.js build`，不要直接用 `npx vite`。构建后用 `git checkout -- frontend/auto-imports.d.ts frontend/components.d.ts frontend/typed-router.d.ts` 还原自动生成文件。
- 工作树的 `node_modules` 不要做指向主仓库的 junction 后再执行 `pnpm install`，否则会写入主仓库；要么在当前工作树执行 `pnpm install --frozen-lockfile`，要么只用 Node 直接调用。

## 权限、金额与 AI 安全

- 改权限点时，同时更新前端权限目录和权限样本，并在提交说明中写明依据。若样本落后于已经收紧的权限，保持收紧结果，不为了通过检查把权限加回去。
- 会计口径使用演示默认值，并标注「真实使用前需核实」。金额统一用 `Money = {amountMinor: int64, currency}`、`SCALE = 10000`，禁止浮点数参与计算。
- agent 继承登录人的有效权限，只能少不能多；每一步都复用网页动作的权限检查。DeerFlow 以独立 Python worker 的 SDK 方式嵌入，不单独部署服务。
- **审批口径（目标设计）：** agent 发起的改账动作最多生成草稿或待审项；没有可用审批人时退回发起它的本人确认后才生效。人提交的单据按审批人解析：配置了审批人就必须审批，法人或老大也不能自批；未配置或解析不到可用账号时直接生效并留痕。现有代码仍按 [ADR 0001 单一写账出口](../adr/0001-single-write-path.md) 执行「不通过审批不写账」，这是现状；08 v4 的解析规则是目标设计。AI 不执行代码、不启用 bash 或沙箱。关闭 AI 后人工流程必须从头走完。风险和审批规则见 [智能体与权限](../domains/智能体与权限.md) 与 [08 第 10 章](../design/08-后端模块与API设计.md)。

## 数据与机密

- 不读 `CrossERP演示密码.txt`、任何 `.env`、密钥或 token；示例值只用 `<YOUR_API_KEY>` 等占位符。真实卖家数据只留在被忽略的本地目录。
- 原始数据不可改，清洗、校验、去重和实体投射要保留来源；审计日志只追加。发现敏感信息已入库，立即停止并报告。

## 测试与文档

- 不删除、注释或放宽测试和断言；失败要修实现或记录未决问题，不能用 mock 冒充真实验收。
- 推送前按 [测试与回归](测试与回归.md) 完整回归并做密钥扫描，所有检查 exit=0、0 个 FAIL、0 个 ESLint error 后，才允许普通推送到 `origin main`。
- 同一事实只写一处。先改 08、实体 YAML 或 OpenAPI，再更新引用文档；历史证据只补说明，不改结论。
