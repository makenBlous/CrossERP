# 供应链域指南

## 1. 范围与所属分期

覆盖商品与 SKU、组合装、库存台账、移动加权成本、补货计划、采购、到岸成本、物流和仓库。主流程属于 P1–P2；移动加权成本、到岸成本和库存/总账核对属于 P3；对应 08 第 8.1 节和 [`07-成本记账与补货计划补齐`](../design/07-成本记账与补货计划补齐.md)。

## 2. 状态

- **已实现（代码核实）：** 当前后端有导入、对账、利润和基础数据库模型；没有供应链域的完整 `catalog`、`inv`、`proc`、`logi` JSON API。
- **仅静态原型（前端 mock）：** 商品与 SKU：P01–P09；库存：I01–I17、I19–I20；采购：S01–S12；物流：L01–L07。页面清单以 [`pages.ts`](../../frontend/src/config/pages.ts) 和覆盖表为准。
- **仅设计：** 组合装拆分、移动加权库存台账、负库存个案、到岸成本分摊、补货版本冻结、共享库存池和采购申请转草稿，均以 07 和 08 为目标。

## 4. 主要动作、权限与 AI 风险

完整清单看 08 第 5.5、5.7–5.9、5.25 节和 OpenAPI 的 `x-crosserp.*` 字段。实现时动作必须走 `ActionDispatcher`。

| 条目 | 权限点（以目录为准） | 风险与边界 |
|---|---|---|
| SKU、Listing、类目、品牌、仓库和物流商维护 | `item:*`、`listing:*`、`warehouse:*`、对应 `carrier:*` | 中风险，agent 可执行且可撤销；涉及银行信息、成本、汇率时升为高风险草稿。 |
| SKU 映射建议与确认 | `listing:read`、映射写/确认动作 | AI 只能给候选；确认会改数据，必须按中风险留痕。 |
| 库存流水、库存余额和台账查询 | `stock_ledger:read` | 只读，AI 可直接查；金额仍来自确定性台账。 |
| 入库、出库、调拨、盘点过账 | `stock_entry:*`、`stock_reconciliation:*` | 高风险，AI 只能起草/待审；不得绕过库存负数规则。 |
| 补货计算、计划运行、冻结行 | `material_request:read/write/submit/approve` | 计算是低风险；冻结和生成采购申请是中/高，AI 不得自动下采购单。 |
| 采购单、询价、合同、收货、退货 | `purchase_order:*`、`request_for_quotation:*`、`contract:*`、`purchase_receipt:*` | 草稿/非账务改动为中风险；提交、付款、银行信息和账务影响为高风险。 |
| 到岸成本、成本调整和库存/总账核对 | `landed_cost_voucher:*`、`stock_ledger:report` | 预览/试算低风险；分摊、过账和调整凭证高风险，只到待审。 |

AI 解释补货数量时必须引用 `TwinSnapshot`、需求因子和计划行。AI 不计算数量、不填成本、不生成已生效采购单。

## 5. 状态机

- `PurchaseOrder`：`draft → pending → approved → partially_received/received → closed`；提交、审批、收货和关闭动作按 08 目录核对，状态名如实现有差异以实体目录为准。
- `PurchaseReceipt`：`draft → pending → approved → posted`；已过账只能冲回，不能编辑原单。该状态串是依据 07 的流程整理，具体动作映射处标为**推断**。
- `LandedCostVoucher`：`draft → pending → approved → posted → reversed`；分摊预览由代码计算，人只能改分摊基准，不能改结果。
- `InventoryDoc`：草稿、待审批、已过账、已冲回；库存流水只追加。`StockCount` 提交后进入审批，过账后生成差异流水。
- `ReplenishmentPlan`：`running → ready → superseded`；冻结行复制到新版本，计划运行不可并发写同一 SKU 的未冻结行。该状态来自 08/07，页面显示 I19/I20。
- 负库存个案（**推断，来自 07**）：`open → filled → cost_corrected → closed`。默认禁止负库存，只有仓库显式开启平台先发先补例外。

## 6. 审批规则在本域的体现

- 配置了审批人，采购单、收货、库存过账、盘点、到岸成本和成本调整必须审批；法人或主管也不能自批。
- 没有审批人或解析不到可用账号，人提交的非高危动作按 `auto_effective` 直接生效并写审计；AI 发起的高风险/钱账动作进入 `awaiting_initiator`，由发起人本人确认后才生效。
- 供应商银行信息、成本、汇率、分摊和付款保持职责分离。完整流程解析规则见 08 第 4.6 节与 [智能体与权限](智能体与权限.md)。

## 7. 金额与会计口径

- 库存台账金额使用万分位整数；移动加权按 `new_qty = old_qty + q`、`new_amount = old_amount + a`，出库金额按旧结存金额乘数量除旧数量，使用 `ROUND_HALF_UP`，结果落在 `StockMovement`。
- 本位币默认 CNY、存货计价默认移动加权平均；科目 `inventory`、`cogs`、`landed_cost_clearing` 及编号采用 07 演示默认值，**真实使用前需会计核实**。
- 到岸成本按计费重、实重、体积、数量、货值或自定义权重分摊，尾差加到绝对值最大行；已售部分进销售成本，未售部分进库存。
- 采购暂估按采购价 × 收货数量 × 汇率入库存，发票到达先冲 `grni` 再计应付；差额按库存/销售成本规则处理。具体分录以 07 为准。
- 补货数量是代码计算的派生结果，资金上限按合同价或最近采购价（演示默认，真实使用前需核实）；不自动下单。

## 8. 验收标准

- [ ] 页面 I01–I20、P01–P09、S01–S12、L01–L07 的页面 ID 与 `pages.ts` 和覆盖表一致；mock 页标为静态原型。
- [ ] 通过实体目录检查每个写接口都有权限点、风险级别、状态迁移和审计事件。
- [ ] 运行补货后能看到供给快照、公式版本、冻结行和 `source_suggestion_id`；重新运行只生成新版本。
- [ ] 移动加权、到岸成本尾差、负库存和组合装拆分用整数万分位逐项核对；不出现浮点金额。
- [ ] 采购/库存/到岸成本 AI 开与关各点击一次：关闭 AI 时人工按钮仍能完成，mock 与真实接口切换后结果一致。
- [ ] 配置审批人、无审批人、AI 无审批人三种情形分别验证状态迁移、自批拒绝、留痕和本人确认。

## 9. 未核实事项

- 真实仓库、平台库存、物流商字段和同步频率未核实；页面上的 FBA、海外仓、国内仓是设计范围。
- 移动加权会计政策、科目编码、计费重参数、共享库存池和零结存盘盈均为演示默认值，真实使用前需会计/业务确认。
- 当前工作树尚无完整供应链 JSON API；前端 `implemented` 不等于后端已接通。
