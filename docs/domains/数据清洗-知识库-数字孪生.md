# 数据清洗、知识库与数字孪生指南

## 1. 范围与所属分期

覆盖原件落地、清洗校验、去重、实体投射、版本溯源、事件调度、知识库编译/发布/检索和数字孪生同步/偏差/推演。数据进入在 P1，数字孪生在 P3，知识库和 agent 整理在 P4；依据 08 第 8、9、10 章。

## 2. 状态

- **已实现（代码核实）：** 当前连接器有导入批次、原始行、文件哈希去重、列映射和对账/利润投射；`src/crosserp/agent/rules_search.py` 只有规则 Markdown 的关键词检索。
- **仅静态原型（前端 mock）：** K01–K09、ON01–ON02、F01/F02/F03、D01/D05 等页面；以 [`pages.ts`](../../frontend/src/config/pages.ts) 和覆盖表为准。
- **仅设计：** `CleansingIssue` agent 处理与转交、知识空间/版本/索引、孪生状态/快照/偏差/推演副本尚未在当前后端核实。

## 4. 主要动作、权限与 AI 风险

- 原件上传、批次查看、溯源查询：`integration:import`、`document:read`、`report:read`；查询只读，上传/落地低风险。
- 清洗、补映射、判重复、实体投射：`ingest:*`；不改账的处理为中风险，可撤销，涉及金额/科目/汇率/成本则高风险待审。
- 知识编译、体检、检索重建：`document:write`、`document:approve`；编译/体检低或中，发布按审批规则。
- 孪生同步状态、快照和差异查询：`twin:read`；同步任务低风险，非钱账偏差处理中风险，钱账偏差只能生成草稿。
- 推演副本创建、试算和归档：低风险；`promote` 只生成真实草稿，并重新按原动作权限和风险审批。

完整动作与接口看 08 第 9、5.20、5.24、5.25 节及 OpenAPI。

## 5. 状态机

数据链路固定为：`IngestBatch uploaded → landed → cleansed → projected`，随后写 `EntityVersion`、outbox 事件和调度任务；规则升级不能改旧批次，需新批次替代并用补偿事件冲回。

`CleansingIssue` 进入待处理；agent 先尝试，证据不足、规则冲突、连续失败或钱账影响时转交批次上传人（上传人停用则模块管理员）。该处理顺序来自 08，转交接口尚待实现。

知识页草稿经 `KbReview` 审核后发布；空间没有审批人时按已拍板规则 AI 直接发布并留痕。`KbCompileRun` 按内容哈希增量编译，未变化来源跳过。

`TwinDrift` 可分类、接受已知时间差、转交上传人；钱账偏差只产生盘点/调整/冲销草稿。`TwinScenario` 只能在副本执行，不能直接改真实实体、记账或发外部消息；`promote` 转真实草稿。

## 6. 审批规则在本域的体现

- 清洗问题和知识页草稿的中风险处理可由 agent 自动执行并可撤销；每天只摘要通知。
- 配置审核人时，知识发布必须审批；没配置时直接发布并记录 `no_approver_auto`。AI 整理薪资、合同等敏感空间同样适用，但读取和产出都继承原空间 ACL。
- 任何会改变金额、科目、汇率、成本、库存金额或账务的偏差修正，AI 只能起草，配置审批人就必须审批；无审批人时回到 AI 发起人本人确认。

## 7. 金额与会计口径

- 原始金额按万分位整数保存，清洗不能通过四舍五入“修正”金额；无法解析就生成 `CleansingIssue`。
- 知识页只是解释层，不能作为记账依据；财务事实以 `Settlement`、`Voucher`、`StockMovement` 等确定性实体为准。
- 孪生推演使用快照副本，补货和利润沿用 07 的移动加权、汇率和成本规则；科目、汇兑损益和税率都是演示默认值，**真实使用前需核实**。

## 8. 验收标准

- [ ] 上传同一文件两次按 SHA-256 幂等；原件和原始行可读且不能编辑/删除。
- [ ] 清洗错误被隔离，成功行继续；每个投射实体能查到批次、行号、规则版本、操作者和被代表人。
- [ ] agent 处理清洗问题失败后自动转交上传人；涉及钱账的建议不会直接生效。
- [ ] 知识库 K01–K09、ON01–ON02 的页面 ID 与 mock 一致；MySQL 全文索引使用 ngram 分词，中文检索结果按空间 ACL 和来源实体权限过滤。
- [ ] 薪资/合同空间的 AI 整理只能读取发起者可见来源，产出继承来源 ACL，不进入公共索引。
- [ ] 孪生偏差、快照、按时点回看和推演验证：推演不改真实数据；转草稿后重新检查权限、状态和审批。
