# 财务域指南

## 1. 范围与所属分期

覆盖平台结算导入、对账异常、SKU 利润、成本核算、凭证与总账、期间与反结账、暂估、差额、冲销、期初、税务和外部账套导出。P1 已有结算/对账/利润服务；P3 承担总账、成本、税务和数字孪生；外部账套属于 P4。分期依据 08 第 8.1 节。

## 2. 状态

- **已实现（代码核实）：** `src/crosserp/connectors` 支持 Amazon Settlement Flat File V2、Shopify Payments CSV、通用映射导入；`src/crosserp/recon` 做确定性匹配；`src/crosserp/profit` 做 SKU/订单利润；`src/crosserp/approval` 有审批状态机；`src/crosserp/vouchers` 和 `src/crosserp/ledger/write_service.py` 生成/审批后导出 XLSX；只读网页有 `/imports`、`/profit`、`/issues`、`/vouchers`、`/approvals`。
- **仅静态原型（前端 mock）：** F01–F22、F23–F42 及 I16/I17 的页面声明见 [`pages.ts`](../../frontend/src/config/pages.ts)；真实 `/api/v1` 契约仍按 08 设计切换。
- **仅设计：** MySQL 主库下的总账、税务、完整应收应付、金蝶后用友适配器和跨系统回写，按 08 与 07 实现。

## 3. 涉及的实体

- [`Settlement`](../design/08/ontology-entities.yaml)：平台结算单或打款批次。
- [`ReconRun`](../design/08/ontology-entities.yaml)：一次对账运行及匹配率。
- [`ReconIssue`](../design/08/ontology-entities.yaml)：带原因码的对账异常。
- [`ProfitView`](../design/08/ontology-entities.yaml)：由确定性计算生成的利润只读视图。
- [`Account`](../design/08/ontology-entities.yaml)：会计科目配置。
- [`FxRate`](../design/08/ontology-entities.yaml)：月度或日度汇率配置。
- [`Clearing`](../design/08/ontology-entities.yaml)：结算/付款核销批次。
- [`CashTransaction`](../design/08/ontology-entities.yaml)：平台或银行资金孪生流水。
- [`Voucher`](../design/08/ontology-entities.yaml)：凭证草稿、审批和过账对象。
- [`AccountingPeriod`](../design/08/ontology-entities.yaml)：期间开关与反结账状态。
- [`CogsRun`](../design/08/ontology-entities.yaml)：按库存流水生成成本结转草稿。
- [`FxRevaluation`](../design/08/ontology-entities.yaml)：外币余额重估。
- [`LandedCostVoucher`](../design/08/ontology-entities.yaml)：到岸成本分摊凭证。
- [`OpeningBatch`](../design/08/ontology-entities.yaml)：科目、库存、应收应付期初批次。
- [`VatReturn`](../design/08/ontology-entities.yaml)：VAT 计提/申报准备案卷。
- [`ExportRebateCase`](../design/08/ontology-entities.yaml)：出口退税跟踪案卷。
- [`ExportPackage`](../design/08/ontology-entities.yaml)：已批准的外部账套导出产物。
- [`Approval`](../design/08/ontology-entities.yaml)：所有高风险与钱账动作的审批记录。

现有代码的原因码详见 [`recon-categories.md`](../rules/recon-categories.md)；不要在本文件复制原因码全集。

## 4. 主要动作、权限与 AI 风险

完整动作以 08 第 5.10–5.13、OpenAPI 和实体 YAML 为准。

| 条目 | 代表接口/权限 | 风险 |
|---|---|---|
| 导入结算、订单、成本、汇率 | `/finance/imports`、`integration:import` | 导入落地/投射为低或中；钱账字段变化只生成草稿。 |
| 运行对账、查看异常、处理差异 | `/finance/recon`、`/finance/issues`、`reconciliation:*` | 计算/匹配/差异分析只读或低；标记解释/忽略为中；生成调整凭证为高。 |
| 查看利润、凭证、余额和报表 | `/finance/profit`、`report:read` | 只读，AI 可以直接查询，LLM 不计算金额。 |
| 生成凭证、成本结转、清分、核销、付款 | `journal_entry:*`、`payment_reconciliation:*` | 高风险，AI 只能起草/待审，经唯一写出口生效。 |
| 期间结账、反结账、汇兑重估 | `period_closing_voucher:*`、`exchange_rate_revaluation:*` | 结账和审批决定为高危/真人；反结账按审批解析规则。 |
| 导出金蝶/用友 | `integration:write`、`ledger_target:*` | 对外写账为高危；当前先金蝶，后用友，必须有批准凭证。 |

## 5. 状态机

- `Settlement`：`imported → split → voucher_draft → posted → payout_matched → fx_booked`；映射未确认时停在 `split`。这是 07 B-4.4 的状态串。
- `ReconRun`：创建、运行、完成或失败；匹配状态 `matched/partial`，未匹配由有开放异常且无 match 记录的组表示。详见对账规则文件。
- `Voucher`：`draft → pending → approved → posted → reversed`，驳回回 `draft`；过账后不可编辑，只能全额红字冲销，再重录新凭证。
- `AccountingPeriod`：`open → closing → closed → reopening → open`；结账清单通过后才能关账，反结账申请人不能自批。状态依据 07 B-4.3，`reopening` 名称以实体 YAML 实现为准。
- `OpeningBatch`：`collecting → trial_balanced → pending_approval → live`；科目、库存、应收应付必须同时平衡。
- `Approval`：通用 `draft → pending → approved/rejected`，批准后导出或过账；无审批人和 AI 本人确认分支见第 6 节。

## 6. 审批规则在本域的体现

- 配置审批人就必须审批，不设金额上限；制单人、AI 被代表人和起草人不能审批。
- 没配置或解析不到账号，人提交的单据直接生效并写「无审批人，直接生效」；AI 发起的高风险/钱账动作必须进入 `awaiting_initiator`，由发起人确认。
- `ledger/write_service.py` 是唯一写出口。任何凭证导出、过账或外部账套写入都必须检查批准状态、内容哈希和幂等性；反结账也走相同审批解析。

## 7. 金额与会计口径

- `Money.amountMinor` 使用万分位整数，数据库金额不使用浮点；仅展示边界按 `ROUND_HALF_UP` 到分。
- 现有利润代码用 `Decimal` 和月汇率；订单/SKU 结果缺成本或汇率时保留异常，不猜数。对账金额不四舍五入后再比较。
- 本位币默认 CNY；存货默认移动加权平均；结算清分采用结算单结束日单一汇率；科目编码、`inventory`、`cogs`、`grni`、`fx_diff`、退税率和 VAT 责任方均为演示默认值，**真实使用前需会计/税务核实**。
- 已过账凭证不改。晚到费用、汇兑差额用差额凭证；科目选错用全额红字冲销后重录。期初先试算平衡，结账后不直接改原期间。
- 外部账套顺序：金蝶 XLSX → 用友适配器。当前代码的 `kingdee_xlsx`、`generic_xlsx` 只能在批准后由写服务调用；未实现的平台 API 不得假写入。
