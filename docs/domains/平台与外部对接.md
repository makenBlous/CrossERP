# 平台与外部对接指南

## 1. 范围与所属分期

覆盖文件导入、Amazon、Shopify、领星/赛狐、通知和审批渠道、外部账套与适配器约定。文件导入属于 P1；平台接入、账套适配器和外部 MCP 属于 P4；IM 审批放在 P5 后期。顺序以 08 第 4.11、8.1 节为准。

## 2. 状态

- **已实现（代码核实）：** `src/crosserp/connectors` 有 Amazon Settlement V2、Shopify Payouts、通用映射连接器和 YAML 映射；CLI/网页可导入文件。`src/crosserp/ledger/targets` 有通用 XLSX、金蝶 XLSX 目标。
- **仅静态原型（前端 mock）：** F01–F05、INT01–INT05、G26 等对接/导入页面；页面 ID 以 [`pages.ts`](../../frontend/src/config/pages.ts) 和覆盖表为准。
- **仅设计：** Amazon SP-API、Shopify API、领星 API、IM 审批渠道、完整 outbox worker 和用友目标尚未在当前代码核实。

## 3. 涉及的实体

- [`FileObject`](../design/08/ontology-entities.yaml)：上传文件和哈希。
- [`IngestBatch`](../design/08/ontology-entities.yaml)：所有平台/文件数据的统一批次。
- [`RawRecord`](../design/08/ontology-entities.yaml)：不可变原始记录。
- [`MappingRule`](../design/08/ontology-entities.yaml)：列、费用和字段映射版本。
- [`SyncJob`](../design/08/ontology-entities.yaml)：平台同步任务。
- [`Connector`](../design/08/ontology-entities.yaml)：可插拔连接器元数据。
- [`PlatformAuth`](../design/08/ontology-entities.yaml)：平台授权配置。
- [`LedgerTarget`](../design/08/ontology-entities.yaml)：外部账套导出目标。
- [`IntegrationLog`](../design/08/ontology-entities.yaml)：适配器调用和失败留痕。
- [`ChannelPlugin`](../design/08/ontology-entities.yaml)：通知/审批渠道插件。
- [`NotifyChannel`](../design/08/ontology-entities.yaml)：渠道配置与健康状态。
- [`Approval`](../design/08/ontology-entities.yaml)：平台内审批及后续渠道决定命令。
- [`ExportPackage`](../design/08/ontology-entities.yaml)：已批准导出产物。

## 4. 主要动作、权限与 AI 风险

适配器只做格式转换、收发和健康检查；权限、状态、审批、审计、实体投射统一回到 `ActionDispatcher`、`IngestBatch` 或 `ledger/write_service.py`。完整动作看 08 第 4.11、5.17、5.21 节及 OpenAPI。

| 场景 | 权限/动作 | 风险 |
|---|---|---|
| 文件上传、预览、列映射 | `integration:import`、`FileObject.create`、`MappingRule` | 上传/预览低风险；投射改变实体为中风险，金额/账务字段为高风险草稿。 |
| 平台拉取 | `SyncJob`、`PlatformConnector.pull` | 只产生原件和批次，低风险；首期不做平台 push。 |
| 审批渠道 | `ApprovalChannel.send_approval_card`、`approvals.decide` | 发送通知可低风险；审批决定是高危，仅真人进入统一决定入口。 |
| 外部账套导出 | `LedgerTarget.export`、`ExportPackage` | 对外写账高危；必须经过批准、内容哈希和幂等 outbox。 |
| 健康检查/测试连通 | `health_check()`、模型/连接测试 | 只读或低风险；不把测试结果当业务写入。 |

平台顺序固定为：**文件导入 → Amazon → Shopify → 领星**。账套顺序固定为：**金蝶 → 用友 → 其他**。各平台账号、权限、API 可用范围目前均标「未核实」。

## 5. 状态机

- `IngestBatch`：`uploaded → landed → cleansed → projected`；同一文件哈希幂等，规则升级用新批次替代旧批次，旧投射用补偿事件冲回。
- `SyncJob`：`queued → running → succeeded/failed/cancelled`，由 CrossERP 后台调度，失败可重试。
- `Connector`/`PlatformAuth`：配置、启用、暂停/失效等状态按实体 YAML；具体转移属**推断**，实现以目录为准。
- `Approval`：先平台内 `draft → pending → approved/rejected`，IM 回调只能产生决定命令，仍由服务端校验签名、重放、身份、内容哈希和自批规则。
- `ExportPackage`：生成、等待批准、导出成功/失败；导出失败不回滚业务单据，只记失败并通知管理员。

## 6. 审批规则在本域的体现

- 平台内审批先于 IM；配置审批人就必须审批，发送卡片不等于批准。
- 没有可用审批人时，人发起的单据按无审批人直接生效并留痕；AI 发起的高风险/钱账导出必须退回发起人本人确认。
- 外部回调不能绕过审批；任何适配器不得直接写凭证、账套或业务表，必须调用统一动作执行器/写服务。

## 7. 金额与会计口径

- 导入金额先保留原文和解析失败信息，标准金额用万分位整数；EU `95,00` 等格式按连接器/站点规则解析，不全局替换逗号。
- 平台结算、对账、利润和凭证金额由确定性代码处理，适配器不能改数；汇率和科目采用 07 演示默认值，**真实使用前需核实**。
- 金蝶目标当前以 XLSX 模板为准；用友接口、科目映射、外部账套编码和平台 API 权限都是未核实事项。

## 8. 验收标准

- [ ] 文件导入、Amazon、Shopify、通用映射三类连接器按表头读取，未知列/费用类型保留并生成异常；重复文件不重复投射。
- [ ] INT01、F01–F05、G26 的页面 ID 与 mock/real 契约一致；每个适配器有 manifest、版本、capabilities、configSchema 和 health check。
- [ ] 适配器失败走 outbox 重试和 `IntegrationLog`，不回滚已提交的实体；同一 `dedupKey` 不重复发送。
- [ ] 审批决定、回调签名、防重放、内容哈希和权限复核均在服务端验证；IM 渠道未上线前不能假装可用。
- [ ] 金蝶导出未经批准被拒绝；批准后生成可追溯 `ExportPackage`，用友入口明确标为设计/未核实。
- [ ] 依次验证文件导入 → Amazon → Shopify → 领星和金蝶 → 用友的开关/状态，不跨阶段提前启用。

## 9. 未核实事项

- Amazon SP-API、Shopify、领星/赛狐真实 API 字段、账号权限、限流和同步频率未核实；文件导入是当前唯一可靠入口。
- IM 审批渠道延后；具体飞书、企业微信、钉钉选择未定。
- 外部账套用友适配器、真实金蝶模板和平台回写接口未实现/未验证。
