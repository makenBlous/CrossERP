## 2. 前端总体结构

### 2.1 建议形态

做成独立的 Vue 3 单页应用，通过 JSON 接口访问现有 FastAPI，而不是继续用服务器渲染的 Jinja 页面堆新功能。理由：Vuexy 本身就是这套结构；经营看板、对话、看板拖拽、权限菜单都更适合前端路由。

推荐目录（实施时再创建，本文不改代码）：

```text
frontend/
  src/
    pages/                 # 文件即路由，对齐 Vuexy 的 unplugin-vue-router
      login.vue
      dashboard/
      catalog/
      orders/
      inventory/
      procurement/
      logistics/
      finance/
      ads/
      crm/
      approvals/
      agent/
      audit/
      admin/
      account/
    views/                 # 较重的页面区块，从 Vuexy views 的组织方式借鉴
    components/            # CrossERP 自己的业务组件（不提交 Vuexy 源码）
    navigation/            # 菜单树，按权限过滤
    plugins/               # vuetify、i18n、casl、router
    stores/                # Pinia：当前用户、店铺、通知、字典
    api/                   # 由 OpenAPI 生成的客户端 + 少量手工封装
    utils/
  index.html
  package.json
```

`frontend/` 放在何处，取决于 maken 对 Vuexy 许可证的选择（见总览第 6 节）。在未决定之前，设计按「逻辑上属于 CrossERP 前端」来写，不假设它已经可以公开。

### 2.2 和现在 Jinja 页面如何共存

不搞一天切完全部页面。建议分三步：

1. **接口先行**：在 FastAPI 上增加 `/api/v1/...` JSON 接口，权限、会话、审计与现在网页共用。现在的 Jinja 页面继续可用。
2. **新界面并行**：本地启动 Vue 开发服务，把接口代理到 `127.0.0.1:8001`（或当时实际端口）。先替换首页看板、利润、异常、导入这些「看出效果」的页面。
3. **收口**：全部目标页切完后，FastAPI 在生产模式托管前端构建结果；旧 Jinja 路由可暂时保留作备用，再择期下线。不删除现有测试。

登录建议先继续用**服务器端会话 Cookie + CSRF**（现有机制已经有锁定和审计），Vue 请求时在头里带上 CSRF 令牌。Vuexy 示例里有 `jwt-decode`，那是模板自带的演示登录方式，不作为必须迁移目标。「推断」Cookie 会话更符合现有安全和审计设计。

### 2.3 权限菜单、状态、多语言、接口客户端

- **菜单**：前端维护一份菜单清单，每项标注所需权限点。登录后向 `/api/v1/auth/me` 取角色和权限，用 Vuexy 已集成的 CASL 控制菜单显示和按钮。无权访问的地址进入 `pages/not-authorized.vue`。
- **数据范围**：界面上始终提供「当前店铺 / 全部店铺」筛选。店铺级授权表见数据模型；未做隔离前，「推断」接口仍返回当前公司全部店铺，但页面先把筛选做好。
- **状态**：Pinia 保存当前用户、可选店铺、未读通知、字典。列表筛选条件保存在路由查询参数里，便于分享和刷新。
- **多语言**：使用已有的 `vue-i18n`，先做简体中文，预留英文。接口错误码由前端翻译，不直接展示底层异常。
- **接口客户端**：后端 OpenAPI（FastAPI 自动生成）导出后，用生成工具生成 TypeScript 类型和请求函数。页面不手写路径字符串，避免前后端各改各的。

### 2.4 角色在界面上的大致可见范围

沿用现有五种角色（`src/crosserp/auth/permissions.py`）。**2026-11-10 更新**：固定角色改为「权限表 + 可编辑角色」体系，下表五种角色只是旧代码里的角色，升级后会映射到 16 个预置角色模板（见第 20.11 节和 `02-后端架构与模块.md` 第 13 节）：

| 角色 | 主要能看的菜单 |
|---|---|
| admin | 全部，含系统设置、平台授权、智能体接入、模块开关 |
| operator | 工作台、商品、订单、导入、异常处理、凭证草稿、审批提交、智能体对话；后期开放采购/库存操作类页面 |
| finance | 工作台、财务报表、审批决定、凭证下载、智能体对话；不管理用户 |
| viewer | 工作台、只读报表和看板、智能体对话；无修改按钮 |
| auditor | 工作台只读、审计、安全日志、LLM 监控与评测只读；不修改业务数据 |

一个人可以同时拥有多个角色，与现有设计一致。单人模式仍由系统设置控制 **【已被 08 v4 第 12.1 节取代】**，自批会在审计里标记。

## 18. 现在先做的页面优先级

### 20.12 企业知识库与新人上手（12）

- **公司资料**：规章制度、SOP、产品资料、供应商资料、合同模板、系统帮助文档。
