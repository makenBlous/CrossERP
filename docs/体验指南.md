# CrossERP Windows 体验指南

**状态：已实现能力的本机演示说明。** Vue 前端仍是静态 mock；本指南演示的是现有 FastAPI/Jinja 页面和 CLI。正式环境以 MySQL 8.4 LTS 为主库，本地演示优先使用 SQLite。

## A：SQLite 本机演示

在仓库根目录打开 PowerShell：

~~~powershell
uv sync --all-extras
uv run crosserp demo --check --no-browser
uv run crosserp serve --host 127.0.0.1 --port 8000
~~~

打开 http://127.0.0.1:8000/login。演示库使用合成数据；登录密码由初始化命令现场设置或由 demo 临时生成。不要把密码、API key 或 token 写入仓库。

需要固定管理员账号时，使用新的 SQLite 文件并在终端输入密码：

~~~powershell
$env:CROSSERP_DATABASE_URL = "sqlite:///C:/CrossERP-demo/admin.db"
uv run crosserp init --admin-username admin --admin-password-stdin
uv run crosserp serve --host 127.0.0.1 --port 8000
~~~

## B：MySQL 8.4 演示

正式环境建议使用 MySQL 8.4 LTS。请准备本机未提交的环境配置，连接串必须使用 utf8mb4，并按 [数据库说明](database.md) 和 [测试与回归](dev/测试与回归.md) 做启动自检。不要把密码写进命令、文档或 Git。

数据库就绪后，执行迁移、导入合成数据、对账和利润计算；具体命令以当前 CLI 的 help 和 [后端开发指南](backend/README.md) 为准。浏览器仍访问本机绑定的 127.0.0.1 地址。

## C：PostgreSQL 兼容回归

PostgreSQL 只用于兼容回归或满足 [08 第 11.3 节](design/08-后端模块与API设计.md#113-什么情况下必须换-postgresql) 的替换条件，不是正式环境默认数据库。使用占位连接串运行 db marker：

~~~powershell
$env:CROSSERP_TEST_DATABASE_URL = "postgresql+psycopg://<USER>:<PASSWORD>@127.0.0.1:5432/crosserp"
uv run pytest -m db
~~~

## 角色与安全

现有实现包含 admin、operator、finance、viewer、auditor 等角色。不要为演示临时放宽权限。按 [08 v4 第 4.6、12.1 节](design/08-后端模块与API设计.md) 的目标规则，人提交的单据按审批人解析：配置了审批人必须审批，且不能批准自己提交的单据；未配置或解析不到可用账号时直接生效并留痕。agent 发起的改账动作最多到草稿或待审；没有可用审批人时退回发起它的本人确认后才生效。AI 只读工具继承登录人权限，不能执行代码；关闭 AI 后，导入、对账、异常、审批和凭证等人工路径仍应可用。现有代码仍按 [ADR 0001](adr/0001-single-write-path.md) 的「不通过审批不写账」规则执行。

遇到 403 先核对角色和权限，遇到数据异常先保留 CLI 输出和页面提示，不直接改数据库。开发规则和完整回归命令见 [docs/dev/开发规则.md](dev/开发规则.md) 与 [docs/dev/测试与回归.md](dev/测试与回归.md)。
