# CrossERP Windows 体验指南

这份指南给第一次使用 CrossERP 的人。命令都在 **PowerShell** 中执行，并且都从仓库根目录执行。指南使用项目自己的 `.venv`；不要把项目装到系统 Python 或其他公共环境。

## 先记住三件事

1. 浏览器地址是 `http://127.0.0.1:8000`。只在本机使用时不要改成 `0.0.0.0`。
2. 演示密码只在初始化时由你设置，或由 `demo` 第一次运行时在终端随机生成。仓库没有固定演示密码；终端没有保存密码时，按本指南最后的“清空数据”重新开始。
3. AI 问答必须配置你自己的模型服务地址、模型名和 API key。三项都留空时，AI 页面会提示未配置，这是正常的安全行为。

## A：不安装 Docker，用 uv + SQLite 跑演示

### A-1. 拉代码并创建项目环境

**1. 拉取最新代码**

```powershell
git pull origin main
```

应该看到 `Already up to date.`，或者看到本次更新的提交列表。

如果提示没有权限，先在 GitHub 登录有仓库权限的账号；如果提示有本地改动，先保存这些改动，再重试，不要用 `git reset --hard` 覆盖它们。

**2. 确认 uv 可用**

```powershell
uv --version
```

应该看到 `uv 0.13.x`。如果提示找不到命令，请从 uv 官方安装说明安装 uv，然后重新打开 PowerShell。

**3. 安装到当前项目的 `.venv`**

```powershell
uv sync --all-extras
```

应该看到依赖解析完成，并在项目根目录出现 `.venv`。如果 `.venv` 没有出现，确认当前目录确实是 CrossERP 根目录，再运行一次；不要改用系统 Python。

**4. 确认命令使用项目解释器**

```powershell
& .\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
```

应该打印当前仓库下的 `...\CrossERP\.venv\Scripts\python.exe`。如果路径指向别的 Python，停止使用那个终端，回到仓库根目录重新执行第 3 步。

### A-2. 建立 SQLite 演示库并启动网页

**5. 指定一个不会碰正式数据的演示库**

```powershell
$env:CROSSERP_DATABASE_URL = "sqlite:///C:/CrossERP-demo/demo.db"
```

应该没有错误。这个文件只用于演示；正式库默认是用户目录下的 `.crosserp\data.db`。

**6. 导入样本、对账并计算利润**

```powershell
& .\.venv\Scripts\python.exe -m crosserp demo --db $env:CROSSERP_DATABASE_URL --no-browser
```

应该看到导入摘要、匹配率和利润店铺数量，并看到一行类似“演示账号 demo，随机密码（仅本次显示）”。请把随机密码临时记在密码管理器里；它不会写入仓库，也不会再次显示。若数据库已存在而导入被判重复，删除本节末尾说明的演示库后重跑。

**7. 启动本地网页**

```powershell
& .\.venv\Scripts\python.exe -m crosserp serve --host 127.0.0.1 --port 8000
```

应该看到 `CrossERP 服务启动 http://127.0.0.1:8000`。这个窗口要一直开着，停止时按 `Ctrl+C`。

如果 8000 端口已占用，改用 `--port 8001`，然后浏览器打开 `http://127.0.0.1:8001`。如果网页提示数据库连接错误，确认每个 PowerShell 窗口都重新设置了 `CROSSERP_DATABASE_URL`。

**8. 打开登录页**

在浏览器地址栏打开：

```text
http://127.0.0.1:8000/login
```

用户名是 `demo`，密码是第 6 步终端当次显示的随机密码。应该登录到 CrossERP 首页并看到“导入记录、SKU 利润、异常清单、凭证、审批台、审计”等链接。

如果密码忘了，不要猜密码或把密码写进仓库；停止服务，删除 `C:\CrossERP-demo\demo.db`，重新执行第 6 步即可生成新密码。

### A-3. （可选）不用随机 demo 账号，自己设置管理员

需要可重复的账号时，可以新建另一个 SQLite 文件：

```powershell
$env:CROSSERP_DATABASE_URL = "sqlite:///C:/CrossERP-demo/admin.db"
```

```powershell
& .\.venv\Scripts\python.exe -m crosserp init --admin-username admin
```

命令会在终端隐藏输入管理员密码两次，要求至少 10 个字符，最后打印“数据库已就绪”。这个密码由你现场设置，仓库不会记录它。之后用同一个 `CROSSERP_DATABASE_URL` 启动 `serve`。

### A-4. 配置 AI（可选）

**9. 设置你自己的模型服务配置**

```powershell
$env:CROSSERP_MODEL_BASE_URL = "https://你的模型服务地址/v1"
```

```powershell
$env:CROSSERP_MODEL = "你的模型名"
```

```powershell
$secureKey = Read-Host "请输入模型 API key" -AsSecureString; $env:CROSSERP_API_KEY = [System.Net.NetworkCredential]::new('', $secureKey).Password
```

最后一条会隐藏输入。不要把真实 key 写进 `.env`、文档或 Git。若 `/ask` 显示“未配置模型”，检查三项变量是否在**启动网页的同一个 PowerShell 窗口**中设置，并重启 `serve`。

## B：安装 Docker Desktop，用 PostgreSQL profile

Docker 方式适合想体验 PostgreSQL 的用户。先安装并启动 Docker Desktop；PowerShell 中应能运行 `docker`。

**1. 拉取代码**

```powershell
git pull origin main
```

应该看到代码已更新或 `Already up to date.`。本指南仍然建议执行 `uv sync`，因为它能让你在宿主机运行检查命令；网页和数据库会运行在 Docker 中。

**2. 创建项目 `.venv`**

```powershell
uv sync --all-extras
```

应该在项目根目录出现 `.venv`。如果只体验 Docker，也不要把宿主机的公共 Python 当成项目环境。

**3. 复制部署配置**

```powershell
Copy-Item deploy\.env.example deploy\.env
```

应该出现 `deploy\.env`。这个文件只在本机保存，不能提交。

**4. 设置自己的密码**

```powershell
notepad deploy\.env
```

把 `POSTGRES_PASSWORD`、`CROSSERP_*_PASSWORD` 和 `CROSSERP_ADMIN_PASSWORD` 全部改成自己的值，至少 10 个字符；保留 PostgreSQL profile 的 URL，并确认 `CROSSERP_COOKIE_SECURE=0`（本地是 HTTP）。管理员用户名由 `CROSSERP_ADMIN_USERNAME` 决定。不要把这些密码复制到仓库或聊天记录。

应该能保存文件而不出现语法错误。如果启动时提示 `请配置 ...`，说明 `.env` 没保存或变量名被改坏。

**5. 构建并启动 PostgreSQL profile**

```powershell
docker compose --env-file deploy/.env --profile pg up -d --build
```

应该看到 `postgres`、`migrate`、`app` 启动，且 `migrate` 最终退出码为 0。第一次构建可能需要几分钟。

如果提示 Docker daemon 未运行，启动 Docker Desktop；如果提示端口 8000 被占用，修改 `CROSSERP_PORT=8001` 后重新执行本步，并把后面的地址中的 8000 换成 8001。如果迁移失败，先看第 6 步日志，不要删除数据库卷。

**6. 检查健康状态**

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

应该看到包含 `status : ok` 和版本号的结果。若失败，运行下面的命令查看原因：

```powershell
docker compose --env-file deploy/.env --profile pg logs --tail 100 app migrate postgres
```

修正配置后再执行 `up -d`；不要把日志中的密码复制到文档。

**7. 导入合成演示数据并生成报表**

```powershell
docker compose --env-file deploy/.env --profile pg exec app crosserp demo-import
```

应该每个样本文件输出一行导入结果，重复执行会显示“已导入过，跳过”。

```powershell
docker compose --env-file deploy/.env --profile pg exec app crosserp reconcile --period 2026-10
```

应该看到各店铺的组数、匹配数和匹配率。

```powershell
docker compose --env-file deploy/.env --profile pg exec app crosserp profit --period 2026-10
```

应该看到 SKU 数、收入、平台费和利润摘要。如果显示“尚未有当前对账结果”，先重新执行上一条对账命令。

**8. 登录网页**

打开：

```text
http://127.0.0.1:8000/login
```

用户名和密码就是 `deploy\.env` 中的 `CROSSERP_ADMIN_USERNAME` 与 `CROSSERP_ADMIN_PASSWORD`。应该进入首页。如果登录失败，确认登录信息没有多余空格，并查看 `docker compose --env-file deploy/.env --profile pg logs app`；不要重置数据库来试密码。

## 五种角色的完整体验路径

CrossERP 的五种角色是 `admin`（管理员）、`operator`（运营）、`finance`（财务）、`viewer`（查看者）和 `auditor`（审计）。为了演示职责分离，建议用管理员在 `/admin/users` 分别建立四个账号；每个密码都由你现场输入，不能写到仓库。管理员账号也可以暂时拥有全部角色，但这只能用于个人演示。

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| admin | 全部页面、用户、设置、导入和审批 | 无 |
| operator | 导入、处理异常、提交审批、看报表、问 AI | 批准、下载凭证、看审计和 AI 监控 |
| finance | 看报表、批准审批、下载已批准凭证、问 AI | 导入、处理异常、提交审批 |
| viewer | 看导入记录、利润、异常和问 AI | 所有修改、审批、下载、审计和监控 |
| auditor | 看报表、审计链、审计导出、登录安全日志和 AI 监控 | 业务修改、审批和凭证下载 |

下面的页面地址都以 `http://127.0.0.1:8000` 开头；8001 端口时替换端口即可。登录后每完成一步都应看到页面内容或成功提示；如果看到“你没有权限做这件事”，这是角色限制，换成表格中允许的角色，不要降低权限矩阵。

### 1. admin：从准备到审计走一遍

1. 登录 `/admin/users`，为 operator、finance、viewer、auditor 各建一个账号。应该在用户列表看到这些用户；看不到时确认当前账号确实是 `admin`。
2. 在第二个 PowerShell 窗口运行 `& .\.venv\Scripts\python.exe -m crosserp demo-import`。应该看到导入批次；导入失败先看 `/imports` 的失败原因。
3. 运行 `& .\.venv\Scripts\python.exe -m crosserp reconcile --period 2026-10`，再运行 `& .\.venv\Scripts\python.exe -m crosserp profit --period 2026-10`。应该看到匹配率和利润摘要。
4. 打开 `/issues` 查看原因码和建议；在异常详情中填写说明并选择“已解释/已解决/忽略”。没有处理控件时，说明当前版本只提供列表入口，请改用 operator 的同一路径处理，不要直接改数据库。
5. 以 operator 登录 `/profit`，点“提交审批”；以 finance 登录 `/approvals`，打开待审批单，填写审批意见并批准。
6. 以 operator 运行 `& .\.venv\Scripts\python.exe -m crosserp voucher draft --store <店铺名> --period 2026-10 --as operator`。应该打印凭证 UUID 和借贷合计相等；随后用打印出的 UUID 运行 `& .\.venv\Scripts\python.exe -m crosserp voucher submit <凭证UUID> --as operator`。
7. finance 在审批详情批准凭证，打开 `/vouchers` → 凭证详情 →“下载金蝶格式”。应该下载 `.xlsx`；未批准时下载必须被拒绝。
8. 以允许 AI 的账号打开 `/ask` 提问，例如“2026-10 哪个 SKU 利润最高？”。应该看到回答和可追溯引用；没有模型配置时按 A-4 配置。
9. 打开 `/audit` 查看业务链，打开 `/llm` 查看 AI 调用量、拒答、费用和慢调用。应该能看到“正常”和统计数字；审计链异常时停止继续演示并保留页面提示。

### 2. operator：导入、对账、异常、提交审批

1. 用 operator 登录 `/imports`，应该看到导入批次；没有批次时在命令窗口执行 `& .\.venv\Scripts\python.exe -m crosserp demo-import`。
2. 运行 `& .\.venv\Scripts\python.exe -m crosserp reconcile --period 2026-10`，再运行 `& .\.venv\Scripts\python.exe -m crosserp profit --period 2026-10`。应该看到匹配率和利润摘要。
3. 打开 `/issues`，在异常详情填写至少 5 个字的说明并选择状态。应该看到状态改变；没有处理控件时是当前网页限制，请保留 CLI 输出并让管理员检查版本。
4. 在 `/profit` 点“提交审批”。应该在 `/approvals?state=pending` 看到待审批单。
5. 打开 `/ask` 做一次只读问答。应该有引用；operator 打开 `/audit` 或 `/llm` 会被拒绝，这是预期权限。

### 3. finance：批准并下载凭证

1. 用 finance 登录 `/approvals?state=pending`，应该看到 operator 提交的待审批单。
2. 打开审批详情，检查期间、店铺、利润摘要和“新鲜度正常”，填写审批意见后点“批准”。数据已改变时会提示重新提交，不要强行批准。
3. 打开 `/vouchers`，进入已批准凭证详情，点“下载金蝶格式”。应该下载 Excel 文件；未审批凭证不能下载。
4. 打开 `/ask` 查询只读数据。finance 不能导入、处理异常或查看审计，看到 403 时不要修改角色。

### 4. viewer：只读检查结果

1. 用 viewer 登录 `/imports`、`/profit`、`/issues`，应该能看到导入、利润和异常内容。
2. 打开 `/ask` 问一个数据问题，应该看到回答和引用（模型已配置时）。
3. 尝试点审批、下载或修改按钮时应被拒绝或看不到按钮；这是只读角色的预期结果。若 viewer 能修改数据，立即停止演示并检查角色配置。

### 5. auditor：审计和 AI 监控

1. 用 auditor 登录 `/audit`，应该看到业务哈希链状态、操作者、动作和改前改后差异。
2. 打开 `/audit/verify`，应该返回业务链和 security 链均正常。
3. 打开 `/audit/export` 下载审计包。应该得到一个 zip；这是导出审计证据，不是业务数据修改。
4. 打开 `/security-log` 查看登录和权限事件，再打开 `/llm` 查看调用量、费用、拒答率和 P50/P95 慢调用。
5. auditor 不能导入、处理异常、批准或下载凭证；被拒绝是正常的职责分离。

## 看不到内容时的排查顺序

1. 先看服务窗口是否仍在运行，再访问 `http://127.0.0.1:8000/health`，预期是 `status=ok`。
2. 确认当前 PowerShell 的 `CROSSERP_DATABASE_URL` 与启动服务的窗口相同；A 方式确认它指向 `C:\CrossERP-demo\demo.db`，B 方式确认使用了 `--env-file deploy/.env`。
3. 确认已经运行 `demo-import`、`reconcile`、`profit`，并在 `/imports` 看批次状态。
4. 遇到 403 先核对角色；不要为了演示给 viewer、auditor 或 finance 临时增加不属于它的权限。
5. 遇到 AI 错误，检查三项模型变量是否都在服务进程启动前设置；API key 过期或模型服务不可达时，先按模型服务商的说明处理。

## 停止服务和清空演示数据

### SQLite A 方式

**停止网页服务**：在运行 `serve` 的窗口按 `Ctrl+C`。预期 PowerShell 返回提示符。

**删除演示库（不可恢复，请确认路径是演示库）**：

```powershell
Remove-Item C:\CrossERP-demo\demo.db -Force
```

应该不再存在该文件。重新运行 A-2 第 5、6 步会得到一套全新的演示数据和随机密码。不要删除用户目录下的正式 `data.db`，除非你明确知道那也是演示库。

### Docker B 方式

**停止服务但保留数据**：

```powershell
docker compose --env-file deploy/.env --profile pg down
```

应该看到容器停止；再次执行 B-5 会继续使用原数据。

**清空 PostgreSQL 演示数据（不可恢复）**：

```powershell
docker compose --env-file deploy/.env --profile pg down -v
```

应该删除 `pg-data` 等 Compose 数据卷。之后重新执行 B-5 会初始化空数据库；管理员密码仍以新的 `deploy\.env` 内容为准。这个命令只对本地演示环境使用，确认没有要保留的数据后再执行。
