# 前端开发规范

> **适用范围：** CrossERP `frontend/` 的页面、组件、mock service 和未来真实接口适配层。**状态：** 现有页面是仅静态原型（前端 mock）；本文件中的真实接口和审批提示是长期开发规范或 08 的设计约束。

## 1. 复用优先级与复用审计

新增 UI 按以下顺序查找：

1. Vuexy 已有页面或组件；
2. Vuetify 组件；
3. 确认没有合适实现后，才新写项目组件。

先看 [组件复用审计](./component-reuse-audit.md) 和 [整合后审计](./component-reuse-audit-final.md)，再看 [第三批页面来源](./vuexy-sources-batch3.md)。新增或保留自写组件时，在对应批次报告或新的审计记录中写明：查过的 Vuexy 路径、可复用组件、没有复用的原因、页面范围和权限适配。业务数据、路由和权限不要塞进通用展示组件。

优先复用 `ListPage`、`DetailPage`、`FormDrawer`、`FormPage`、`StatusChip`、`MoneyText`、`PermissionGate`、`KpiCard`、`ConfirmHost` 以及 `src/views/` 中的批次薄壳。

## 2. 页面目录、路由和权限点

新增页面按以下顺序操作：

1. 在 `src/config/pages.ts` 的 `pageCatalog` 增加 `id`、路径、分组、中英文名称、目的、区块、阶段和角色。
2. 填写明确的 `requiredPermissions` 或 `requiredAnyPermissions`，权限名必须来自 `src/config/permissions.ts` 的 `permissionCatalog` 或 08 / ontology 原名。不要用“能打开菜单”代替权限。
3. 需要出现在侧栏时设置 `showInMenu: true`，`menuGroups` 必须已有对应分组；菜单 `to` 使用 `{ path }`。
4. 先用占位路由验证页面目录和权限。完成 `.vue` 页面后再把 `implemented` 改为 `true`。
5. 路由由 `src/plugins/1.router/index.ts` 自动发现并由 `guards.ts` 做页面守卫；菜单由 `src/navigation/build-nav.ts` 根据当前角色过滤。
6. 页面调用只经过 `src/api/*.ts`。新增 service 时同时写 mock 实现、未来 `/api/v1` 注释、权限检查和审计行为。

`pageCatalog` 是页面目录的事实来源，`permissionCatalog` 是权限点目录的事实来源。后端接入后，`GET /api/v1/auth/me` 的有效权限和数据范围优先；前端守卫只负责及时反馈。

## 3. 金额、日期和时区

- 金额类型统一使用 `Minor`，即万分位整数（`SCALE = 10000`）；解析、加减、换算和展示统一调用 `src/utils/money.ts`。金额字段不得使用 `float`。
- `minorFromCents` 只用于当前 HR 旧数据迁移；真实接口按 08 第 4.9 节把 HR `*Cents` 统一为 `Minor`，新代码不再扩散 `*Cents`。
- 中间计算保留万分位整数，最终展示才按币种舍入；组件 `MoneyText` 只格式化，不猜汇率。汇率和会计默认值属于演示值，真实使用前需核实。
- 真实接口的时间使用带时区的 UTC ISO-8601。页面展示按用户时区转换；不要用浏览器本地时间参与业务计算。当前 mock 中仍有日期字符串和 `toISOString()` 混用，统一日期展示工具**未核实**，接入真实接口时补齐。

## 4. 表单与审批按钮

表单优先使用 Vuetify 校验和 `@core/utils/validators`，通过 `FormDrawer` / `FormPage` 提交。业务动作放在 `src/api/`，组件只收集输入和显示结果。

涉及审批、凭证、付款、库存或其他数据变化的提交按钮，旁边必须先显示 `GET /api/v1/workflow/rules/resolve` 的结果，使用以下三种明确文案之一：

- `由谁审批：<账号或角色>`；
- `提交即生效`（没有审批人，服务端直接生效并留痕）；
- `需你确认`（AI 发起的钱账或高风险动作找不到可用审批人时退回发起人）。

按钮不能在前端自行判断金额门槛或绕过审批。真实审批统一先取得待审批单，再调用 `POST /api/v1/approvals/{id}/decide`；AI 建议统一经 `POST /api/v1/agent/suggestions`。

## 5. AI、对话与人工兜底

当前 `MockAgentAdapter` 只读取已存储 mock 结果。助手可以解释、列证据和起草建议，不能计算或改写金额、匹配结果、利润、库存或凭证。写操作最多进入待审批草稿；人工表单、审批和导入流程在 AI 关闭后仍然可用。

对话必须遵守以下约束：

- 请求上下文绑定当前页面、路由、选中记录和登录人。前端 mock 层已在 `../src/api/agent-module.ts` 实现 `bindInitiator(permissionKey)` 发起人快照，并由 `assertInitiatorUnchanged` 在延迟返回后拒绝登录人或角色变化；`recordAgentQuestion`、`recordSuggestionStep` 和 `submitAgentSuggestion` 都使用这组校验。真实后端按通行证回查发起人的对应做法仅是 [08 第 12 章](../../docs/design/08-后端模块与API设计.md) 的设计，当前未接入。
- `useChatInflight` 在登出、切换用户、切换角色时使旧请求失效；`../src/components/chat/useChatInflight.ts` 通过请求号、登录态和 `userId` 阻止旧回调写入新会话，`../src/pages/agent/chat.vue` 与 `../src/components/biz/AssistantDrawer.vue` 均已使用它。
- `../src/stores/session.ts` 的 `logout()` 清理会话并调用 `window.location.replace(loginPageHref())` 整页跳转到登录页；`../src/App.vue` 只有在 `session.isLoggedIn && aiMode.isEnabled` 时挂载全局 `AssistantDrawer`，所以未登录或 AI 关闭时不显示浮动助手。降级模式的只读限制在 `../src/stores/ai-mode.ts` 暴露了 `isReadOnly`，但聊天入口未据此拦截建议提交，完整限制**未核实**。
- `../src/agent/mock-adapter.ts` 的 `MockAgentAdapter` 读取已存储结果并明确不重算或改账；金额只用于只读卡片展示，建议卡经 `../src/api/agent-module.ts` 的 `submitAgentSuggestion` 生成待审批记录，不直接改金额、库存或凭证。工资查询调用 `listGapDRecords('HR12', actor)`，只返回绑定当前 `userId` 的工资条。其他“当前权限可见数据”和敏感文档对象范围的逐项代码依据**未核实**。
- 页面不显示“我的通行证”或手动作废通行证入口。通行证自动签发、静默续期和作废由服务端处理，用户无感。
- 不提供 AI 执行代码、bash 或沙箱的入口；未来脚本只能通过注册函数或 MCP 工具，并沿用权限和风险分级。

## 6. 模型设置

模型设置只允许 3 个字段：`baseUrl`、`apiKey`、`model`，加一个连通性测试动作。`apiKey` 输入后只显示掩码，服务端加密存储，不回显、不进入日志。当前代码只有 `Agent` 类型和 mock 页面，真实模型设置页面与接口**仅设计，未实现**；不要据此新增 Gateway、通行证或部署配置 UI。

## 7. 变更记录

同一变更需要同时更新对应文档、`CHANGELOG.md` 和任务记录。历史报告只补充历史标记，不改当时验收结论；现行规则只在本文件和 [对接真实接口](./对接真实接口.md) 固化。
