# 对接真实接口

> **适用范围：** 将 `frontend/` 的 mock service 切换到 CrossERP 后端 JSON 接口。**状态：** 仅设计；当前页面仍使用 mock，本文没有修改代码。

## 1. 契约来源

接口、实体、动作和风险标注以 08 v4、[OpenAPI 草案](../../docs/design/08/openapi-draft.yaml) 和 [页面与 API 对照表](../../docs/design/08/page-api-coverage.csv) 为准。OpenAPI 的字段使用 camelCase，金额是 `Money = { amountMinor: int64, currency }`，`amountMinor` 为万分位整数，时间为 UTC ISO-8601。页面现有 `src/types` 只作为兼容层，契约漂移应通过生成类型的编译检查暴露。

## 2. 切换方式

后端上线后按以下方式逐步切换：

1. 保留 `src/api/*.ts` 的函数名、参数和返回类型；页面组件不改。
2. 在 `src/api/http.ts` 集中处理 Cookie、CSRF、POST 的 `Idempotency-Key`、错误码到 `FlowError` 的映射和 401 登录跳转。
3. 用 `VITE_API_MODE=mock|real` 控制总模式，用 `VITE_API_REAL_MODULES=catalog,fin,...` 列出已切换模块。每个 service 通过模块开关在 mock 实现和 HTTP 适配之间选择。
4. 每个模块先用 mock 跑一遍现有点击验证，再用真实接口跑同一组点击；数据、状态、权限拒绝和审计结果一致后，才把模块加入 `VITE_API_REAL_MODULES`。
5. 会话改由 `GET /api/v1/auth/me` 提供用户、角色、有效权限和数据范围。前端保留权限守卫，但后端是最终裁决者。
6. 审批类 service 先查询待审批单，再调用统一决定入口；页面按钮按 `GET /api/v1/workflow/rules/resolve` 显示“由谁审批 / 提交即生效 / 需你确认”。

切换层必须保持页面、组件、路由和 mock 回归不变。按代码看，当前页面确实只依赖 `src/api/`，mock 逻辑集中在 `src/mocks/services/`，因此“只换 service 适配层”可行；真实 HTTP 层、生成类型和双跑脚本尚未实现。

## 4. HR 金额字段迁移

`src/types/gap-d.ts` 当前仍有 `baseMinCents`、`salaryCents`、`grossCents` 等字段。接真实 HR 接口时，service 适配层把它们映射为 `Minor` 的 `amountMinor`，页面使用 `MoneyText` 展示。迁移完成前不得新增 `*Cents` 字段，也不能把 cents 当作元或浮点数。

## 5. 按 P0–P5 分期

分期和页面覆盖以 08 第 8.1 节为准：

| 期 | 前端切换范围 | 说明 |
|---|---|---|
| P0 | 认证、`auth/me`、文件、任务、店铺、幂等、权限、审计、审批、实体目录 | 先让会话和权限来源稳定，再切业务页面。 |
| P1 | 商品与主数据、导入、结算、对账、异常、利润、科目、汇率、映射、导出 | 复用现有财务 service，页面组件不改。 |
| P2 | 订单、库存、补货、采购、物流、通知和工作台 | 验证“补货 → 采购 → 收货 → 头程 → 出库”链路。 |
| P3 | 应收应付、核销清分、总账、成本、税务、费用和预算、数字孪生推演 | 写账只能由后端 ledger 和审批控制，推演写副本。 |
| P4 | 智能体、知识库、平台集成、金蝶/用友适配、委托通行证和 DeerFlow SDK | DeerFlow 作为独立 worker 进程中的 SDK 嵌入，不部署独立 DeerFlow 服务。 |
| P5 | 人事、薪资、行政、CRM、广告和后期 IM 审批 | 模块注册表中的 HR、行政当前默认关闭。 |

每期都要对每个模块执行 mock / real 双跑点击验证，比较结果、错误、权限、审计和金额；不一致就停留在 mock。切换记录写入对应批次报告，并链接 OpenAPI operationId、实体动作和权限点。
